# Northwind Cloud Docs — Docusaurus at enterprise scale

A working demo built to answer real questions from a conference talk about Docusaurus: can it handle
~100 product lines, per-product versioning, and localization into 8+ languages without falling over?

This repo is 15 fictional "Northwind Cloud" product docs, each its own versioned/independent
`@docusaurus/plugin-content-docs` instance, translated into 9 locales (English + 8 languages), served from
one Docusaurus site. Read the reasoning inside the site itself at `/docs/architecture`,
`/docs/versioning-strategy`, `/docs/i18n-strategy`, and `/docs/performance` — or below for the short
version and how to run it yourself.

## Prerequisites

- **Node.js 18.0+** (built and tested on Node 26; check with `node --version`)
- **npm** (ships with Node; check with `npm --version`)
- Optional: [Vercel CLI](https://vercel.com/docs/cli) if you want to deploy your own copy

If you don't have Node installed:

```bash
# macOS (Homebrew)
brew install node

# or via nvm (any OS)
curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/master/install.sh | bash
nvm install --lts
```

## Getting started

```bash
git clone https://github.com/wordsnlogic/docusaurus-enterprise-demo.git
cd docusaurus-enterprise-demo
npm install
npm start
```

`npm start` opens a local dev server at `http://localhost:3000` with hot reload. That's the whole setup —
all product docs and translations are already generated and committed to this repo.

## Building for production

```bash
npm run build
npm run serve   # preview the production build locally at http://localhost:3000
```

This builds all 9 locales for all 15 product instances (17 plugin/version combinations once Atlas's and
Beacon's `1.0.0` versions are counted) into `build/`. See `/docs/performance` on the live site, or
[`BUILD_STATS.md`](./BUILD_STATS.md) in this repo, for actual timing from this machine.

## Repo layout — how the pieces map to the architecture

```
docusaurus.config.ts        # wires up i18n locales + one plugin instance per product (generated
                             # from data/products.json — see productDocsPlugins)
data/products.json          # the single source of truth for what products exist
scripts/generate-content.mjs# (re)generates every product's English + translated docs from templates
sidebars-product.js         # shared autogenerated sidebar used by every product instance

docs/                        # the DEFAULT docs instance — this is meta-documentation about the
                              #   architecture itself (architecture.md, i18n-strategy.md, etc.)
docs-<product>/              # one folder per product, e.g. docs-atlas/, docs-beacon/ — each is its
                              #   own plugin instance's source docs
atlas_versioned_docs/        # Atlas's frozen 1.0.0 snapshot (created via `docs:version:atlas`)
beacon_versioned_docs/       # same, for Beacon
atlas_versions.json          # ["1.0.0"] — the list of versions Atlas has cut
i18n/<locale>/
  docusaurus-plugin-content-docs-<product>/current/      # translated current docs for that product
  docusaurus-plugin-content-docs-<product>/version-1.0.0/# translated docs for that product's 1.0.0
src/pages/products.tsx       # the /products catalog page (generated from data/products.json)
```

## Regenerating or adding content

**Add a 16th product:** add one entry to `data/products.json`, then:

```bash
node scripts/generate-content.mjs   # generates docs-<newproduct>/ + i18n/*/…-<newproduct>/current/
npm start                            # docusaurus.config.ts picks it up automatically — no other edits needed
```

**Regenerate all product docs from the templates** (e.g. after editing the phrase dictionaries in
`scripts/generate-content.mjs`):

```bash
node scripts/generate-content.mjs
```

**Cut a new version for a product:**

```bash
npx docusaurus docs:version:<product-id> <version>   # e.g. docs:version:atlas 2.0.0
```

**Add an 10th language:** add the locale code to `i18n.locales` and `i18n.localeConfigs` in
`docusaurus.config.ts`, add a phrase-dictionary entry to `STRINGS` and the `LOCALES` array in
`scripts/generate-content.mjs`, then rerun the generator.

## Deploying

This demo deploys to [Vercel](https://vercel.com) (zero-config for Docusaurus):

```bash
npm install -g vercel
vercel login
vercel --prod
```

Or GitHub Pages, using Docusaurus's built-in deploy command:

```bash
GIT_USER=<your-github-username> npm run deploy
```

## Troubleshooting

- **`Unable to read Git info` during build** — the sitemap plugin reads last-modified dates from git; run
  `git init && git add -A && git commit -m "init"` before your first `npm run build` if you started from a
  fresh copy without git history (this repo already has it).
- **Build feels slow past ~30-40 products** — see `/docs/performance` on the live site for the selective/CI
  build strategy; don't just keep adding plugin instances to one full build indefinitely.
- **A locale shows 404s on some pages** — Docusaurus does *not* fall back to the default locale for missing
  translated docs (see `/docs/i18n-strategy`); the translated markdown file for that page/locale genuinely
  needs to exist.
